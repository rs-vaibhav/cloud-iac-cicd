# Cloud Infrastructure as Code with CI/CD (Azure · Terraform · AKS · GitHub Actions)

A 3-tier application on Azure where **every resource is created by Terraform** and **every change goes
through a pull request pipeline** (tests, image CVE scan, `terraform plan`, security scan) before it
is applied and deployed to Kubernetes automatically.

```
                         Internet
                            │ 80/443 (NSG allow-list)
            ┌───────────────▼─────────────────────────── VNet 10.10.0.0/16 ─────────┐
            │  snet-aks 10.10.0.0/20                                                │
            │  ┌─────────── AKS (Azure CNI overlay, Calico, Entra ID RBAC) ───────┐ │
            │  │ ingress-nginx ─► notes-web (nginx) ─► notes-api (FastAPI) ──┐    │ │
            │  │                     tier 1                tier 2           │    │ │
            │  └──────────────────────────────────────────────────────────────┼────┘ │
            │  snet-db 10.10.16.0/24 (delegated, NSG: 5432 from AKS only)     ▼      │
            │                 PostgreSQL Flexible Server 16 (private, no public IP)  │
            └────────────────────────────────────────────────────────────────────────┘
   ACR (images, pulled via kubelet managed identity)   Key Vault (DB URL, read by CSI driver)
   Log Analytics (Container Insights)                  Storage account (remote Terraform state)
```

## What's in here

| Path | What it does |
|---|---|
| `infra/bootstrap/` | One-time creation of the remote state storage account (versioned, Entra-ID auth only, no access keys) |
| `infra/modules/network` | VNet, AKS + DB subnets, NSGs (default-deny), subnet delegation, private DNS zone for PostgreSQL |
| `infra/modules/aks` | AKS with autoscaling, Azure CNI overlay, Calico network policy, workload identity, Entra ID + Azure RBAC, local accounts disabled, Key Vault CSI driver, Container Insights; AcrPull role for nodes |
| `infra/modules/postgres` | PostgreSQL 16 Flexible Server, VNet-integrated, TLS enforced, random admin password, optional zone-redundant HA |
| `infra/modules/acr` | Container registry, admin user disabled |
| `infra/main.tf` | Wires modules together; stores the DB connection string in Key Vault (RBAC mode) |
| `infra/envs/` | `dev` / `prod` variables and backend configs — same code, different sizes |
| `app/` | `web` (nginx static UI + reverse proxy) and `api` (FastAPI + SQLAlchemy) with Dockerfiles (multi-stage, non-root) |
| `k8s/` | Kustomize base + dev/prod overlays: probes, resource limits, HPA, PDB, zero-trust NetworkPolicies, restricted Pod Security, SecretProviderClass |
| `.github/workflows/pr.yml` | PR gate: ruff + pytest, Docker build, Trivy CVE scan, kubeconform, `terraform fmt/validate`, TFLint, Checkov, `terraform plan` posted as a PR comment |
| `.github/workflows/deploy.yml` | On merge: `terraform apply` → build & push to ACR → `kustomize` deploy → wait for rollout, **auto-rollback** on failure → smoke test. Prod needs manual approval |

## Security choices

- **No secrets in Git or CI**: GitHub → Azure uses **OIDC federated credentials**; the DB password is
  generated by Terraform, written to Key Vault and mounted into pods by the CSI driver.
- **Least privilege**: AKS pulls from ACR with its managed identity (`AcrPull`), pods read Key Vault with
  `Key Vault Secrets User`, cluster access is Entra ID + Azure RBAC with local admin disabled.
- **Network**: database has no public endpoint; NSGs allow only 80/443 to AKS and 5432 from AKS to DB;
  inside the cluster a default-deny NetworkPolicy only allows ingress → web → api → DB.

## Run it

### Locally (no Azure needed)
```bash
docker compose up --build        # http://localhost:8080
cd app/api && pip install -r requirements.txt pytest httpx && pytest -q
```

### On Azure
```bash
# 0. prerequisites: az cli, terraform >= 1.6, kubectl, kubelogin
az login && export ARM_SUBSCRIPTION_ID=$(az account show --query id -o tsv)

# 1. remote state (once) - pick a globally unique storage account name and put it in envs/*.backend.hcl
cd infra/bootstrap && terraform init && terraform apply -var storage_account_name=sttfstate<yourname>

# 2. dev environment
cd .. && make -C .. plan ENV=dev && make -C .. apply

# 3. tear down when finished to save credits
make -C .. destroy ENV=dev
```

### CI/CD setup
1. Create an Entra ID app registration with a **federated credential** for this GitHub repo
   (`repo:<you>/<repo>:environment:dev` and `:environment:prod`) and give it `Contributor` +
   `User Access Administrator` on the subscription (needed for the role assignments).
2. Add repo secrets `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID`.
3. Create GitHub environments `dev` and `prod`; add required reviewers to `prod`.

## Verified

- `terraform fmt -check` and `terraform validate` pass against azurerm 4.x (root module and bootstrap)
- `kustomize build` renders both overlays; `kubeconform -strict` validates 12/12 core resources
  (the SecretProviderClass CRD is skipped)
- API test suite passes against SQLite

## Cost note
Dev uses `Standard_B2s` nodes, a burstable `B1ms` PostgreSQL and Basic ACR. Run `make destroy` after
demos to avoid charges.
